# Map

Core files implemented for the talkbox commands:

- [talkbox.sh](talkbox.sh) - the dispatcher which routes `onbox`, `netbox` and `offbox` (via `talkbox.sh <container>` or a matching symlink) through one container-parameterised action: it parses the options, assembles the read mounts, write mounts (bind-mount args via `mount_args` for a bind write style, a single `mount_entries` parse plus `mount_volume_args` volume args built from the same parsed entries for a volume write style, selected by the `write_style` config field), ports and the raw effective IP deny and allow sets via `deny_allow_args` for nft-enforcing containers (per the `nft_enforce` config field), prepares the host git repo for the lifecycle verbs, and dispatches every verb directly to the container-parameterised cores (`run_container` for the default create verb, `run_recreate` for recontain/rebuild, `run_rm_container`/`run_rm_image` for the removal verbs, and `run_fetch`/`run_merge`/`run_sync`), always passing the container as the leading argument and the write srcs/dsts namerefs positionally (they stay empty for bind-style containers), threading both sets into the cores that consume them (the `rm-container` dispatch passes only the project, because the write volumes are discovered by inspecting the container in `lib/containers.sh`).
- [lib/common.sh](lib/common.sh) - shared utilities module providing the `die()` helper (prints `talkbox: <message>` to stderr and exits with the given code), `strip_comment()` (removes everything from the first `#` onwards), `trim()` (strips leading/trailing whitespace), `clean_line()` (comment-strip followed by trim), `read_list_file()` (appends the comment-stripped, trimmed, non-empty lines of a file to a caller-declared array via a nameref, as a no-op for an absent file), the ordered-dedup pair `dedup_ordered()`/`dedup_last_ordered()` (first-occurrence-wins and last-occurrence-wins order-preserving deduplication into an output nameref, the last-wins variant built on the first-wins one over the reversed sequence) and `plan_no_net_run()` (appends the shared no-network temporary-container prefix tokens `podman run --rm --network=none --userns=keep-id:uid=1000,gid=1000` to a caller-declared array).
- [lib/definitions.sh](lib/definitions.sh) - the per-container configuration record: a single pure case-based lookup `container_config <field> <container>` that reads as a table and defines, for each of onbox/netbox/offbox, the pasta network suffix, nft deny/allow enforcement, write style (bind/volume), named worktree volume (yes/no), root image (yes/no), populate policy (none/host/source-else-host) and the ordered default inheritance parents (empty meaning base); sourced by `talkbox.sh` and `lib/containers.sh`, it holds all per-container knowledge outside the naming degenerate cases, so every former container-conditional branch point consults it instead.
- [lib/naming.sh](lib/naming.sh) - pure helpers producing `<project-base>`, `<project-slug>`, the shared base image name (honouring the `TALKBOX_BASE_IMAGE` override, defaulting to `talkbox/base:latest`), the container-agnostic `<project-slug>.<container>.gitdir` gitdir-volume name and the `<dest-slug>` derivation for a dest path; the shared slug normalisation (lowercase, non-alphanumerics to hyphens, collapse runs, strip edge hyphens) lives in a single `slugify` helper called by both `project_slug` and `dest_slug` (which keeps its leading/trailing slash stripping as a wrapper detail); all other container names are derived generically by the `*_of` dispatchers in `lib/containers.sh`.
- [lib/options.sh](lib/options.sh) - argument parsing for `onbox`/`netbox`/`offbox` (`-c`/`--command`, `--interactive`, `--noninteractive`, repeatable `--read`/`--write`/`--port`/`--deny-ip`/`--allow-ip`, `--fresh`, `--inherit <source>`, `--gpu`, `--all`, the `fetch`/`merge`/`sync` subcommand verbs with an optional `<branchname>` positional, and the `--recontain`/`--rebuild`/`--rm-container`/`--rm-image` lifecycle verbs), recording the selected command, interactive mode, verb, branch and mount/port/deny-allow/inheritance/GPU selections.
- [lib/mounts.sh](lib/mounts.sh) - parses mount files and CLI specs into depth-ordered, deduplicated `podman` `-v` argument lists per read/write mode (file lines and CLI specs cleaned via the shared `read_list_file`/`clean_line` helpers; identical dests collapsed last-wins via `dedup_last_ordered` plus a last-source map, then ordered shallow-to-deep by a stable depth sort), expanding `~`/`$HOME`/`$PROJECT` and deriving default dests; in write mode every resolved source must be an existing directory (`require_write_dir` dies with a `talkbox:` message naming the source), while read mode accepts files and folders; `mount_volume_args <out> <container> <project> <srcs> <dsts>` emits the volume-style write mounts as named volumes (`<slug>.<container>.write.<dest-slug>`, built via the generic `write_volume_of` dispatcher from `lib/containers.sh`) from the precomputed write srcs/dsts namerefs produced by `mount_entries`, so the write mounts are parsed once per invocation.
- [lib/network.sh](lib/network.sh) - parses `defaults/ports` and CLI `--port` values into the deduplicated, ordered `pasta` `-T,<port>` token list, and computes the raw deduplicated deny and allow sets via `deny_allow_args` (list files read through the shared `read_list_file` and both sets deduplicated via `dedup_ordered`; reading `defaults/deny.ip`/`defaults/allow.ip` and the CLI arrays; the allow set always includes the loopback entries `127.0.0.0/8` and `::1` and the DNS-forward address `169.254.1.1/32`, with no CIDR carving). The deny set is enforced in a container netns via `nft_deny_ruleset`/`plan_nft_deny`/`install_nft_deny`: for each address family with deny entries, `nft_deny_ruleset` emits an interval-set ruleset (table `talkbox_deny`) defining `allowed` and `blocked` sets and an `accept` rule matching `@allowed` placed before the `@blocked` `drop` rule, applied through `podman unshare nsenter -t <PID> -n nft -f -` with `/usr/sbin:/sbin` prepended to the pipeline's `PATH`; when the deny set is non-empty and the PID lookup or the `nft` pipeline fails, `install_nft_deny` surfaces the underlying stderr with a `talkbox:` error and returns non-zero (stopping the container is left to the `containers.sh` wrapper), unless `TALKBOX_STRICT_NFT=0` selects lax mode, which warns and returns 0 as before; the PID lookup runs through `nft_container_pid` (podman inspect stderr suppressed only in lax mode) and both failure modes report through the `nft_fail_or_warn` strict/lax helper carrying each message once, so strict and lax stderr text, return codes and exit statuses are unchanged; an empty deny set causes no invocation.
- [lib/containers.sh](lib/containers.sh) - the container layer, a single config-driven implementation for all three containers (every former per-container branch point collapsed behind `container_config` lookups from `lib/definitions.sh`): the executor cores `run_container`/`run_recreate`/`run_rm_container`/`run_rm_image` (container as the first argument, called directly by talkbox.sh for every verb) share the start-time tail — nft install for nft-enforcing containers via `install_nft_deny_or_die` after `podman start`, then `run_setup_in_container`, then the exec (or the best-effort stop for the recreate path) — and wrap their `execute_plan` calls in a rollback branch (`rollback_creation_and_die` stops and removes the partial container plus the volumes named by the shared `container_volumes` helper before `die`-ing with a `talkbox:` diagnostic); the generic naming dispatchers `container_name_of`/`root_image_of`/`worktree_volume_of`/`write_volume_of` build the `<project-slug>.<container>[.<kind>[.<qualifier>]]` names as one-liners over the container argument, with the onbox worktree degenerating to the host project path; `plan_container` builds the persistent-container `podman create` argument list (workdir, userns, the `pasta_net` network string from the config pasta suffix, cap drops, the conditional git mounts assembled through the shared `plan_git_mounts` token emitter in the pinned host-git → gitdir-volume → merge.sh order, the merge-module and read-only `setup.sh` bind mounts, the `defaults/art` and dotfiles mounts, the prompt and git-identity `--env` flags and the `TALKBOX_GPU` device options); `plan_populate_and_create` runs the unified `plan_container_populate` planner (keyed by the populate-policy field: no populate commands for a none policy, always-host seeding for a host policy — so netbox seeds from the host even under an explicit `--inherit` — and, for a source-else-host policy, a per-volume choice via `plan_volume_populate_from` between the inheritance source's corresponding volume when it is volume-backed and exists and the host source otherwise), then the gitdir-volume creation and the `plan_container` → `podman create` assembly; `plan_recreate` is the single recontain/rebuild planner (build, commit-before-rm for root-image containers with a non-base source, volume removal via `plan_container_volumes_rm`, the shared populate-and-create tail and `podman start`); `plan_rm_container` additionally removes the root image for root-image containers when present; `resolve_inheritance` short-circuits root-image-less containers to base and otherwise resolves through `inherit_source`/`inherit_source_for` (same signature, with the default chains walked from the config parent list and the `--fresh`/`--inherit` overrides unchanged), probing the base image via `ensure_base_image` only when inheriting from base outside an explicit rebuild; `container_write_volumes` enumerates the `<project-slug>.<container>.write.` volumes a still-existing container actually mounts (by `podman inspect`) so removal and recreate do not depend on the removal invocation's write mounts; `container_sync_cmd`/`run_sync_in_container` run the `sync` git commands inside a container's repository (via `podman exec` when the persistent container is running, or a temporary no-network container mounting the gitdir volume, worktree and `/host/git` otherwise).
- [lib/git.sh](lib/git.sh) - host-side git helpers: `git_tracked`/`resolve_git_dir`/`classify_git_dir` (inside/outside/none), `git_mounts_enabled` (git-mount predicate), `host_git_identity` (effective `user.name`/`user.email`, used to propagate the host git identity into containers), `refuse_outside_gitdir`/`absorb_submodules`/`prepare_git_host` (host-side git preparation), the `fetch` action (`plan_fetch` assembles the no-network gitdir-bundle `podman run` into one array and the host `git fetch` into `refs/remotes/<container>` into a second array, executed in turn by the shared `run_bundle_fetch` helper which owns the `mktemp -d` bundle-directory lifecycle for `run_fetch` (per container) and `run_merge`; the `no git history for <container>; create the container first` guard lives once in the gitdir-volume probe pair `gitdir_volume_exists` (non-fatal) / `require_gitdir_volume` (fatal) used by `run_fetch` and `require_git_history`, the latter keeping its additional mountpoint/`HEAD` check), and the `merge`/`sync` actions (`run_merge` fetches from the container's gitdir volume via `run_bundle_fetch` then applies `custom_merge <container>` per branch; `run_sync` resolves host branches and runs `git fetch host` + `custom_merge host` inside the container's repository via `run_sync_in_container`; branch resolution is shared through `resolve_branches`). It also hosts `plan_git_mounts()`, the shared git-mount token emitter (read-only host git dir at `/host/git`, the container gitdir volume at `/working/<base>/.git`, read-only `merge.sh` at `/talkbox/lib/merge.sh`) which appends the mounts named by its trailing selector arguments (`hostgit`, `gitdir`, `merge`) in caller-chosen order for the `plan_container` and `container_sync_cmd` planners.
- [lib/merge.sh](lib/merge.sh) - self-contained, location-agnostic merge module defining `custom_merge()` (DESCENDANT_CHECK plus current-branch Cases 1-3 and other-branch `git branch -f`) and its helpers (`descendant_check`, `worktree_matches_tree`); it issues plain `git` commands against the current working directory so it runs identically on the host and inside containers (mounted read-only at `/talkbox/lib/merge.sh`), and is sourced by `lib/git.sh`.
- [image/Containerfile](image/Containerfile) - shared base image definition used to build `talkbox/base:latest`.
- [image/Containerfile.minimal](image/Containerfile.minimal) - minimal Debian-slim test image definition (git, curl, ca-certificates, the `dev` user, `/working`, `setup.sh`) which `mk_talkbox` swaps into the temp talkbox copy's `image/Containerfile`, so the e2e suite builds `talkbox/base-e2e:latest` instead of the production image.
- [defaults/dotfiles/.bashrc](defaults/dotfiles/.bashrc) - global interactive-shell dotfile which prints the container-type ASCII art banner (guarded by the exported `_TALKBOX_BANNER_SHOWN` sentinel, `TALKBOX_CONTAINER_TYPE` and the bind-mounted art file) and defines the coloured `PS1` prompt with the `<project-slug>.<container-type>` host segment, git aliases and shell conveniences.
- [defaults/art/onbox.txt](defaults/art/onbox.txt) - repo-provided green ASCII art for the `onbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [defaults/art/netbox.txt](defaults/art/netbox.txt) - repo-provided blue ASCII art for the `netbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [defaults/art/offbox.txt](defaults/art/offbox.txt) - repo-provided red ASCII art for the `offbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [defaults/deny.ip](defaults/deny.ip) - repo-provided default IP deny list derived from the IANA Special-Purpose Address Registries (every block with Globally Reachable = FALSE, omitting the loopback and DNS-forwarder entries that are always allowed); it is parsed by `deny_allow_args` for `onbox`/`netbox` and enforced via the nft ruleset in `lib/network.sh`.
- [defaults/allow.ip](defaults/allow.ip) - empty repo-provided default IP allow list parsed by `deny_allow_args`; the effective allow set always also contains the loopback entries `127.0.0.0/8` and `::1` and the DNS-forward address `169.254.1.1/32` appended by `lib/network.sh`.
- [defaults/ports](defaults/ports) - empty repo-provided default port list parsed by `port_args` into the pasta `-T,<port>` forwarding tokens together with the repeatable CLI `--port` values.
- [defaults/read.mounts](defaults/read.mounts) - repo-provided default read-mount spec list parsed by `mount_args`, currently binding the host OpenCode auth file (`~/.local/share/opencode/auth.json`) read-only at `/home/dev/.local/share/opencode/auth.json`.
- [defaults/write.mounts](defaults/write.mounts) - empty repo-provided default write-mount spec list parsed once by `mount_entries` (whose output entries also feed `mount_volume_args`) together with the repeatable CLI `--write` values (netbox/offbox destinations become named volumes).
- [image/setup.sh](image/setup.sh) - in-container setup script (invoked with `podman exec` after `podman start`, under the nft deny list for `onbox`/`netbox`) which copies global then project dotfiles into `/home/dev/`, writes the propagated host git identity (`TALKBOX_GIT_USER_NAME`/`TALKBOX_GIT_USER_EMAIL`) into the global git config, and initializes a fresh git repository in the gitdir volume when present (wiring the `host` remote at `/host/git/` through the shared `ensure_host_remote` helper — `git remote add` falling back to `remote set-url` then `|| true` — used by both the fresh-init and existing-repository branches, setting the working tree, and performing an initial `git fetch host` + `git reset --mixed` to connect to the host history); it exits 0 on completion and the image defines no `ENTRYPOINT`.
