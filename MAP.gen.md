# Map

Core files implemented for the talkbox commands:

- [talkbox.sh](talkbox.sh) - the dispatcher which routes `onbox` (via `talkbox.sh onbox` or an `onbox` symlink) to the onbox action and `netbox`/`offbox` to the shared sandbox action (assembling mounts/ports, computing the raw effective IP deny and allow sets via `deny_allow_args` for `onbox`/`netbox` (both empty for `offbox`), preparing the host git repo, dispatching the lifecycle verbs and the `fetch` subcommand, and threading both sets into every container `run_*` executor).
- [lib/common.sh](lib/common.sh) - shared utilities module providing the `die()` helper (prints `talkbox: <message>` to stderr and exits with the given code), `strip_comment()` (removes everything from the first `#` onwards), `trim()` (strips leading/trailing whitespace), `clean_line()` (comment-strip followed by trim), `read_list_file()` (appends the comment-stripped, trimmed, non-empty lines of a file to a caller-declared array via a nameref, as a no-op for an absent file), the ordered-dedup pair `dedup_ordered()`/`dedup_last_ordered()` (first-occurrence-wins and last-occurrence-wins order-preserving deduplication into an output nameref, the last-wins variant built on the first-wins one over the reversed sequence) and `plan_no_net_run()` (appends the shared no-network temporary-container prefix tokens `podman run --rm --network=none --userns=keep-id:uid=1000,gid=1000` to a caller-declared array).
- [lib/naming.sh](lib/naming.sh) - pure helpers producing `<project-base>`, `<project-slug>`, the shared base image name (honouring the `TALKBOX_BASE_IMAGE` override, defaulting to `talkbox/base:latest`), the onbox/netbox/offbox container names, the netbox/offbox worktree, write-volume, root-image and gitdir-volume names, and the `<dest-slug>` derivation for a dest path; the shared slug normalisation (lowercase, non-alphanumerics to hyphens, collapse runs, strip edge hyphens) lives in a single `slugify` helper called by both `project_slug` and `dest_slug` (which keeps its leading/trailing slash stripping as a wrapper detail).
- [lib/options.sh](lib/options.sh) - argument parsing for `onbox`/`netbox`/`offbox` (`-c`/`--command`, `--interactive`, `--noninteractive`, repeatable `--read`/`--write`/`--port`/`--deny-ip`/`--allow-ip`, `--fresh`, `--inherit <source>`, `--gpu`, `--all`, the `fetch`/`merge`/`sync` subcommand verbs with an optional `<branchname>` positional, and the `--recontain`/`--rebuild`/`--rm-container`/`--rm-image` lifecycle verbs), recording the selected command, interactive mode, verb, branch and mount/port/deny-allow/inheritance/GPU selections.
- [lib/mounts.sh](lib/mounts.sh) - parses mount files and CLI specs into depth-ordered, deduplicated `podman` `-v` argument lists per read/write mode (file lines and CLI specs cleaned via the shared `read_list_file`/`clean_line` helpers; identical dests collapsed last-wins via `dedup_last_ordered` plus a last-source map, then ordered shallow-to-deep by a stable depth sort), expanding `~`/`$HOME`/`$PROJECT` and deriving default dests; `mount_volume_args` additionally emits netbox/offbox write mounts as named volumes (`<slug>.<container>.write.<dest-slug>`).
- [lib/network.sh](lib/network.sh) - parses `defaults/ports` and CLI `--port` values into the deduplicated, ordered `pasta` `-T,<port>` token list, and computes the raw deduplicated deny and allow sets via `deny_allow_args` (list files read through the shared `read_list_file` and both sets deduplicated via `dedup_ordered`; reading `defaults/deny.ip`/`defaults/allow.ip` and the CLI arrays; the allow set always includes the loopback entries `127.0.0.0/8` and `::1` and the DNS-forward address `169.254.1.1/32`, with no CIDR carving). The deny set is enforced in a container netns via `nft_deny_ruleset`/`plan_nft_deny`/`install_nft_deny`: for each address family with deny entries, `nft_deny_ruleset` emits an interval-set ruleset (table `talkbox_deny`) defining `allowed` and `blocked` sets and an `accept` rule matching `@allowed` placed before the `@blocked` `drop` rule, applied through `podman unshare nsenter -t <PID> -n nft -f -` with `/usr/sbin:/sbin` prepended to the pipeline's `PATH`; when the deny set is non-empty and the PID lookup or the `nft` pipeline fails, `install_nft_deny` surfaces the underlying stderr with a `talkbox:` error and returns non-zero (stopping the container is left to the `containers.sh` wrapper), unless `TALKBOX_STRICT_NFT=0` selects lax mode, which warns and returns 0 as before; an empty deny set causes no invocation.
- [lib/containers.sh](lib/containers.sh) - the container layer, consolidated around container-parameterized cores with the fifteen `run_*` executor names (talkbox.sh's dispatch surface) as one-to-three-line delegates: `plan_container` builds the persistent-container `podman create` argument list for onbox/netbox/offbox from the per-type naming dispatch (`container_name_of`/`root_image_of`/`worktree_volume_of`/`write_volume_of`) and the `pasta_net` network-string builder (DNS-forward suffix for onbox/netbox, `-i,lo,-I,talkbox0` for offbox), covering the conditional git mounts (assembled through the shared `plan_git_mounts` token emitter from `lib/git.sh` in the pinned host-git → gitdir-volume → merge.sh order), the merge-module and read-only `setup.sh` bind mounts, the `defaults/art` and dotfiles mounts, the prompt and git-identity `--env` flags and the `TALKBOX_GPU` device options; `plan_recreate` is the single recontain/rebuild planner (build, commit-before-rm, volume removal via `plan_container_volumes_rm`, volume population, gitdir-volume creation, create, start); `plan_rm_container`/`plan_rm_image` and the `create_sandbox`/`run_container`/`run_recreate`/`run_rm_container_any`/`run_rm_image_any` executor cores carry the root-filesystem and read-write-volume inheritance (`inherit_source`/`inherit_source_for`, `plan_netbox_populate`/`plan_offbox_populate` with the offbox netbox-volume fallback, each `cp -a` population run built on the shared `plan_no_net_run` prefix from `lib/common.sh`) over `execute_plan`, with `exec_in_container`/`stop_container` as the shared exec/stop tail; the onbox recontain/rebuild executors run no nft, setup or user command, the sandbox recontain executors probe the base image only when inheriting from base, offbox never installs nft (onbox/netbox do so via `install_nft_deny_or_die` after `podman start`), and `run_setup_in_container` runs setup.sh before the user command or the best-effort stop; `container_sync_cmd`/`run_sync_in_container` run the `sync` git commands inside a container's repository (via `podman exec` when the persistent container is running, or a temporary no-network container — the `plan_no_net_run` prefix with `--workdir` appended, then the shared git-mount tokens from `plan_git_mounts` interleaved with the sync-only worktree volume mount — mounting the gitdir volume, worktree and `/host/git` otherwise).
- [lib/git.sh](lib/git.sh) - host-side git helpers: `git_tracked`/`resolve_git_dir`/`classify_git_dir` (inside/outside/none), `list_submodule_git_dirs` (submodule absorption enumeration), `git_mounts_enabled` (git-mount predicate), `host_git_identity` (effective `user.name`/`user.email`, used to propagate the host git identity into containers), `refuse_outside_gitdir`/`absorb_submodules`/`prepare_git_host` (host-side git preparation), the `fetch` action (`plan_fetch` assembles the no-network gitdir-bundle `podman run` into one array and the host `git fetch` into `refs/remotes/<container>` into a second array, executed in turn by the shared `run_bundle_fetch` helper which owns the `mktemp -d` bundle-directory lifecycle for `run_fetch` (per container) and `run_merge`; the `no git history for <container>; create the container first` guard lives once in the gitdir-volume probe pair `gitdir_volume_exists` (non-fatal) / `require_gitdir_volume` (fatal) used by `run_fetch` and `require_git_history`, the latter keeping its additional mountpoint/`HEAD` check), and the `merge`/`sync` actions (`run_merge` fetches from the container's gitdir volume via `run_bundle_fetch` then applies `custom_merge <container>` per branch; `run_sync` resolves host branches and runs `git fetch host` + `custom_merge host` inside the container's repository via `run_sync_in_container`; branch resolution is shared through `resolve_branches`). It also hosts `plan_git_mounts()`, the shared git-mount token emitter (read-only host git dir at `/host/git`, the container gitdir volume at `/working/<base>/.git`, read-only `merge.sh` at `/talkbox/lib/merge.sh`) which appends the mounts named by its trailing selector arguments (`hostgit`, `gitdir`, `merge`) in caller-chosen order for the `plan_container` and `container_sync_cmd` planners.
- [lib/merge.sh](lib/merge.sh) - self-contained, location-agnostic merge module defining `custom_merge()` (DESCENDANT_CHECK plus current-branch Cases 1-3 and other-branch `git branch -f`) and its helpers (`descendant_check`, `worktree_matches_tree`); it issues plain `git` commands against the current working directory so it runs identically on the host and inside containers (mounted read-only at `/talkbox/lib/merge.sh`), and is sourced by `lib/git.sh`.
- [image/Containerfile](image/Containerfile) - shared base image definition used to build `talkbox/base:latest`.
- [image/Containerfile.minimal](image/Containerfile.minimal) - minimal Debian-slim test image definition (git, curl, ca-certificates, the `dev` user, `/working`, `setup.sh`) which `mk_talkbox` swaps into the temp talkbox copy's `image/Containerfile`, so the e2e suite builds `talkbox/base-e2e:latest` instead of the production image.
- [defaults/dotfiles/.bashrc](defaults/dotfiles/.bashrc) - global interactive-shell dotfile which prints the container-type ASCII art banner (guarded by the exported `_TALKBOX_BANNER_SHOWN` sentinel, `TALKBOX_CONTAINER_TYPE` and the bind-mounted art file) and defines the coloured `PS1` prompt with the `<project-slug>.<container-type>` host segment, git aliases and shell conveniences.
- [defaults/art/onbox.txt](defaults/art/onbox.txt) - repo-provided green ASCII art for the `onbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [defaults/art/netbox.txt](defaults/art/netbox.txt) - repo-provided blue ASCII art for the `netbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [defaults/art/offbox.txt](defaults/art/offbox.txt) - repo-provided red ASCII art for the `offbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [defaults/deny.ip](defaults/deny.ip) - repo-provided default IP deny list derived from the IANA Special-Purpose Address Registries (every block with Globally Reachable = FALSE, omitting the loopback and DNS-forwarder entries that are always allowed); it is parsed by `deny_allow_args` for `onbox`/`netbox` and enforced via the nft ruleset in `lib/network.sh`.
- [defaults/allow.ip](defaults/allow.ip) - empty repo-provided default IP allow list parsed by `deny_allow_args`; the effective allow set always also contains the loopback entries `127.0.0.0/8` and `::1` and the DNS-forward address `169.254.1.1/32` appended by `lib/network.sh`.
- [defaults/ports](defaults/ports) - empty repo-provided default port list parsed by `port_args` into the pasta `-T,<port>` forwarding tokens together with the repeatable CLI `--port` values.
- [defaults/read.mounts](defaults/read.mounts) - repo-provided default read-mount spec list parsed by `mount_args`, currently binding the host OpenCode auth file (`~/.local/share/opencode/auth.json`) read-only at `/home/dev/.local/share/opencode/auth.json`.
- [defaults/write.mounts](defaults/write.mounts) - empty repo-provided default write-mount spec list parsed by `mount_entries`/`mount_volume_args` together with the repeatable CLI `--write` values (netbox/offbox destinations become named volumes).
- [image/setup.sh](image/setup.sh) - in-container setup script (invoked with `podman exec` after `podman start`, under the nft deny list for `onbox`/`netbox`) which copies global then project dotfiles into `/home/dev/`, writes the propagated host git identity (`TALKBOX_GIT_USER_NAME`/`TALKBOX_GIT_USER_EMAIL`) into the global git config, and initializes a fresh git repository in the gitdir volume when present (wiring the `host` remote at `/host/git/`, setting the working tree, and performing an initial `git fetch host` + `git reset --mixed` to connect to the host history); it exits 0 on completion and the image defines no `ENTRYPOINT`.

Core files implemented for the test harness:

- [Makefile](Makefile) - top-level makefile which includes the test harness definitions from `test/runner.mk`.

The remaining harness files live under `test/`:

- [test/runner.mk](test/runner.mk) - defines the `test-unit`, `test-e2e`, `test-canary` and `test-timeout` targets, the `GLOBAL_TEST_TIMEOUT` and `INDIVIDUAL_TEST_TIMEOUT` defaults, and the `lint` and `format` targets.
- [test/run-suite.sh](test/run-suite.sh) - runs a bats suite under the global timeout (via `systemd-run` with a `timeout(1)` fallback), enforces the individual timeout via `BATS_TEST_TIMEOUT`, parses the TAP output and writes the run record for the suite.
- [test/lib.bash](test/lib.bash) - helper functions that parse bats TAP output into totals and failing test names, escape YAML single quotes, and write the YAML run record.
- [test/unit/smoke.bats](test/unit/smoke.bats) - unit smoke tests which verify harness basics such as the timeout environment variables, per-test temporary directories and the bats runner.
- [test/unit/parse-tap.bats](test/unit/parse-tap.bats) - unit tests for `parse_tap()` which source `test/lib.bash` and feed it crafted TAP fragments, covering diagnostic-branch and fallback `FAIL_NAMES` entries (including the `(unnamed)` placeholder for empty descriptions) and the `ok`/`# skip` paths that leave `FAIL` untouched.
- [test/e2e/smoke.bats](test/e2e/smoke.bats) - end-to-end smoke tests which verify the harness from the outside, e.g. that `make` exposes the four test targets and that the runner writes run records.
- [test/e2e/host_http_server.py](test/e2e/host_http_server.py) - e2e `--port` test server which binds a socket to port 0, prints the kernel-assigned port as its sole stdout line, then serves a given directory over HTTP using that already-bound socket (eliminating the probe-then-rebind race).
- [test/canary/false.bats](test/canary/false.bats) - canary tests which intentionally assert something false and are expected to fail under `make test-canary`.
- [test/timeout/hang.bats](test/timeout/hang.bats) - timeout canary test which runs a non-terminating command and is expected to fail under `make test-timeout`.
