# Map

Core files implemented for the talkbox commands:

- [talkbox.sh](talkbox.sh) - the dispatcher which routes `onbox` (via `talkbox.sh onbox` or an `onbox` symlink) to the onbox action and `netbox`/`offbox` to the shared sandbox action (assembling mounts/ports, computing the raw effective IP deny and allow sets via `deny_allow_args` for `onbox`/`netbox` (both empty for `offbox`), preparing the host git repo, dispatching the lifecycle verbs and the `fetch` subcommand, and threading both sets into every container `run_*` executor).
- [lib/common.sh](lib/common.sh) - shared utilities module providing the `die()` helper (prints `talkbox: <message>` to stderr and exits with the given code), `strip_comment()` (removes everything from the first `#` onwards) and `trim()` (strips leading/trailing whitespace).
- [lib/naming.sh](lib/naming.sh) - pure helpers producing `<project-base>`, `<project-slug>`, the shared base image name, the onbox/netbox/offbox container names, the netbox/offbox worktree, write-volume, root-image and gitdir-volume names, and the `<dest-slug>` derivation for a dest path.
- [lib/options.sh](lib/options.sh) - argument parsing for `onbox`/`netbox`/`offbox` (`-c`/`--command`, `--interactive`, `--noninteractive`, repeatable `--read`/`--write`/`--port`/`--deny-ip`/`--allow-ip`, `--fresh`, `--inherit <source>`, `--gpu`, `--all`, the `fetch`/`merge`/`sync` subcommand verbs with an optional `<branchname>` positional, and the `--recontain`/`--rebuild`/`--rm-container`/`--rm-image` lifecycle verbs), recording the selected command, interactive mode, verb, branch and mount/port/deny-allow/inheritance/GPU selections.
- [lib/mounts.sh](lib/mounts.sh) - parses mount files and CLI specs into depth-ordered, deduplicated `podman` `-v` argument lists per read/write mode, expanding `~`/`$HOME`/`$PROJECT` and deriving default dests; `mount_volume_args` additionally emits netbox/offbox write mounts as named volumes (`<slug>.<container>.write.<dest-slug>`).
- [lib/network.sh](lib/network.sh) - parses `defaults/ports` and CLI `--port` values into the deduplicated, ordered `pasta` `-T,<port>` token list, and computes the raw deduplicated deny and allow sets via `deny_allow_args` (reading `defaults/deny.ip`/`defaults/allow.ip` and the CLI arrays; the allow set always includes the loopback entries `127.0.0.0/8` and `::1` and the DNS-forward address `169.254.1.1/32`, with no CIDR carving). The deny set is enforced in a container netns via `nft_deny_ruleset`/`plan_nft_deny`/`install_nft_deny`: for each address family with deny entries, `nft_deny_ruleset` emits an interval-set ruleset (table `talkbox_deny`) defining `allowed` and `blocked` sets and an `accept` rule matching `@allowed` placed before the `@blocked` `drop` rule, applied through `podman unshare nsenter -t <PID> -n nft -f -` with `/usr/sbin:/sbin` prepended to the pipeline's `PATH`; when the deny set is non-empty and the PID lookup or the `nft` pipeline fails, `install_nft_deny` surfaces the underlying stderr with a `talkbox:` error and returns non-zero (stopping the container is left to the `containers.sh` wrapper), unless `TALKBOX_STRICT_NFT=0` selects lax mode, which warns and returns 0 as before; an empty deny set causes no invocation.
- [lib/containers.sh](lib/containers.sh) - base image build, the `plan_onbox`/`plan_netbox`/`plan_offbox` persistent-container argument-list planners (with conditional git mounts, the merge-module and read-only `setup.sh` bind mounts, the `defaults/art` read-only bind mount to `/talkbox/art`, the unconditional `--env TALKBOX_PROJECT_SLUG`/`--env TALKBOX_CONTAINER_TYPE` prompt host flags, the git identity `--env` flags via `plan_git_identity_env` gated on git mounts, the `--device nvidia.com/gpu=all`/`--group-add keep-groups` options appended when `TALKBOX_GPU` is `yes`, and the `--dns-forward,169.254.1.1,--map-guest-addr,none` pasta suffix on the `onbox`/`netbox` network strings only), the lifecycle plan functions, the `execute_plan` runner, and the `run_*` executors which actually run `podman`, including the root-image inheritance planner (`inherit_source`), the no-network volume-population planner (`plan_volume_populate`), the netbox/offbox volume population and lifecycle verbs, and the `container_sync_cmd`/`run_sync_in_container` helpers which run the `sync` git commands inside a container's repository (via `podman exec` when the persistent container is running, or a temporary no-network container mounting the gitdir volume, worktree and `/host/git` otherwise). The `run_*` executors receive the deny-set and allow-set arrays as nameref parameters (both empty for offbox); the `run_onbox`/`run_netbox` executors and the netbox recontain/rebuild executors install the nftables deny rules in the container netns after `podman start` via the `install_nft_deny_or_die` wrapper (which calls `install_nft_deny` and, on failure, stops the container with `STOP_GRACE_SECONDS` and `die`s), while the offbox paths and empty deny sets are no-ops; after the nft step (or after start for offbox), the executors run the in-container setup synchronously via `run_setup_in_container` (a `podman exec setup.sh` which stops the container and `die`s on failure) before the user command or the final `podman stop`.
- [lib/git.sh](lib/git.sh) - host-side git helpers: `git_tracked`/`resolve_git_dir`/`classify_git_dir` (inside/outside/none), `list_submodule_git_dirs` (submodule absorption enumeration), `git_mounts_enabled` (git-mount predicate), `host_git_identity` (effective `user.name`/`user.email`, used to propagate the host git identity into containers), `refuse_outside_gitdir`/`absorb_submodules`/`prepare_git_host` (host-side git preparation), the `fetch` action (`plan_fetch` assembles the no-network gitdir-bundle `podman run` into one array and the host `git fetch` into `refs/remotes/<container>` into a second array, run in turn by `run_fetch`), and the `merge`/`sync` actions (`run_merge` fetches from the container's gitdir volume via the same two-array `plan_fetch` then applies `custom_merge <container>` per branch; `run_sync` resolves host branches and runs `git fetch host` + `custom_merge host` inside the container's repository via `run_sync_in_container`; branch resolution is shared through `resolve_branches`).
- [lib/merge.sh](lib/merge.sh) - self-contained, location-agnostic merge module defining `custom_merge()` (DESCENDANT_CHECK plus current-branch Cases 1-3 and other-branch `git branch -f`) and its helpers (`descendant_check`, `worktree_matches_tree`); it issues plain `git` commands against the current working directory so it runs identically on the host and inside containers (mounted read-only at `/talkbox/lib/merge.sh`), and is sourced by `lib/git.sh`.
- [image/Containerfile](image/Containerfile) - shared base image definition used to build `talkbox/base:latest`.
- [defaults/dotfiles/.bashrc](defaults/dotfiles/.bashrc) - global interactive-shell dotfile which prints the container-type ASCII art banner (guarded by the exported `_TALKBOX_BANNER_SHOWN` sentinel, `TALKBOX_CONTAINER_TYPE` and the bind-mounted art file) and defines the coloured `PS1` prompt with the `<project-slug>.<container-type>` host segment, git aliases and shell conveniences.
- [defaults/art/onbox.txt](defaults/art/onbox.txt) - repo-provided blue ASCII art for the `onbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [defaults/art/netbox.txt](defaults/art/netbox.txt) - repo-provided cyan ASCII art for the `netbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [defaults/art/offbox.txt](defaults/art/offbox.txt) - repo-provided red ASCII art for the `offbox` container, rendered by the `.bashrc` banner block on interactive shell start.
- [image/setup.sh](image/setup.sh) - in-container setup script (invoked with `podman exec` after `podman start`, under the nft deny list for `onbox`/`netbox`) which copies global then project dotfiles into `/home/dev/`, writes the propagated host git identity (`TALKBOX_GIT_USER_NAME`/`TALKBOX_GIT_USER_EMAIL`) into the global git config, and initializes a fresh git repository in the gitdir volume when present (wiring the `host` remote at `/host/git/`, setting the working tree, and performing an initial `git fetch host` + `git reset --mixed` to connect to the host history); it exits 0 on completion and the image defines no `ENTRYPOINT`.

Core files implemented for the test harness:

- [Makefile](Makefile) - top-level makefile which includes the test harness definitions from `test/runner.mk`.

The remaining harness files live under `test/`:

- [test/runner.mk](test/runner.mk) - defines the `test-unit`, `test-e2e`, `test-canary` and `test-timeout` targets, the `GLOBAL_TEST_TIMEOUT` and `INDIVIDUAL_TEST_TIMEOUT` defaults, and the `lint` and `format` targets.
- [test/run-suite.sh](test/run-suite.sh) - runs a bats suite under the global timeout (via `systemd-run` with a `timeout(1)` fallback), enforces the individual timeout via `BATS_TEST_TIMEOUT`, parses the TAP output and writes the run record for the suite.
- [test/lib.bash](test/lib.bash) - helper functions that parse bats TAP output into totals and failing test names, escape YAML single quotes, and write the YAML run record.
- [test/unit/smoke.bats](test/unit/smoke.bats) - unit smoke tests which verify harness basics such as the timeout environment variables, per-test temporary directories and the bats runner.
- [test/unit/parse-tap.bats](test/unit/parse-tap.bats) - unit tests for `parse_tap()` which source `test/lib.bash` and feed it crafted TAP fragments, covering diagnostic-branch and fallback `FAIL_NAMES` entries (including the `(unnamed)` placeholder for empty descriptions) and the `ok`/`# skip` paths that leave `FAIL` untouched.
- [test/e2e/smoke.bats](test/e2e/smoke.bats) - end-to-end smoke tests which verify the harness from the outside, e.g. that `make` exposes the four test targets and that the runner writes run records.
- [test/e2e/host_http_server.py](test/e2e/host_http_server.py) - e2e `--port` test server which binds a socket to port 0, prints the kernel-assigned port as its sole stdout line, then serves a given directory over HTTP using that already-bound socket (eliminating the probe-then-rebind race).
- [test/canary/false.bats](test/canary/false.bats) - canary tests which intentionally assert something false and are expected to fail under `make test-canary`.
- [test/timeout/hang.bats](test/timeout/hang.bats) - timeout canary test which runs a non-terminating command and is expected to fail under `make test-timeout`.
