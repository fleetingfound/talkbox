# Build: Phase 11a — Entrypoint readiness synchronization (tmpfs sentinel)

Status: **SUCCESS**

Implemented [Phase 11a](.llm/gen/plans/phase-11a-entrypoint-readiness-sync.gen.md) (per the selected design in [Entrypoint readiness synchronization mechanism](.llm/gen/choices/entrypoint-readiness-sync.gen.md), Option A — tmpfs sentinel): `plan_onbox`, `plan_netbox` and `plan_offbox` in [lib/containers.sh](../../../lib/containers.sh) now emit the literal `--tmpfs /run/talkbox` create option pair (propagated to podman create through the recontain/rebuild planners), a new `wait_for_entrypoint <ctr>` helper runs a single bounded `podman exec` polling loop (150 × 0.1 s ≈ 15 s) for the `/run/talkbox/ready` sentinel and calls `die` on expiry, `run_onbox`/`run_netbox`/`run_offbox` invoke that helper after `podman start` and before the user-command `podman exec` (never in the one-shot `podman run --rm` paths), and [image/entrypoint.sh](../../../image/entrypoint.sh) writes the sentinel as its final pre-`exec` action — writing directly when the tmpfs permits and falling back to `sudo -n touch` when the tmpfs is root-only, because rootless podman remounts `--tmpfs` mountpoints with mode 01755 after a container stop/restart (and via committed root images), which denies the `dev` user a plain `touch`; the sentinel write is skipped entirely when `/run/talkbox` is absent (one-shot containers, which never race and need no sentinel).

Verified: `make test-unit` passes 216/216; `make test-e2e` passes 68/68 (against a rebuilt `talkbox/base:latest` image containing the updated entrypoint; the single earlier e2e failure was the known orphan-container environment fragility documented in [failing-tests-review](.llm/gen/reviews/failing-tests-review.gen.md) and planned for [Phase 11b](.llm/gen/plans/phase-11b-e2e-teardown-hygiene.gen.md), which disappeared once the orphan containers from a debug session were removed).
