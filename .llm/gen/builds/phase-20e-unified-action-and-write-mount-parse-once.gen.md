# Build: Phase 20e — unified container action in talkbox.sh and single write-mount parse

Status: SUCCESS

Implements [Phase 20e](../plans/phase-20e-unified-action-and-write-mount-parse-once.gen.md) against the behaviour pinned by the pre-implementation test pass (documented in [tests/phase-20e-unified-action-and-write-mount-parse-once](../tests/phase-20e-unified-action-and-write-mount-parse-once.gen.md)). `onbox_action`/`sandbox_action` in [talkbox.sh](../../../talkbox.sh) are merged into one container-parameterised `container_action <container>`: read mounts, ports and (for `onbox`/`netbox`, empty for `offbox`) the raw IP deny/allow sets are assembled once, write mounts are assembled per container kind (bind-mount args via `mount_args` for `onbox`; one `mount_entries` parse plus `mount_volume_args` for `netbox`/`offbox`), and every lifecycle verb dispatches uniformly through the container-parameterised `run_${container}`/`run_${container}_*` executor names. Because the existing delegates keep their test-pinned signatures (the onbox ones take no write srcs/dsts and manufacture empty dummies internally, exactly as before), the unified action omits the two srcs/dsts slots for `onbox` via a small `write_entries` array and passes them for `netbox`/`offbox`; [lib/containers.sh](../../../lib/containers.sh) gains four one-line onbox-named delegates (`run_onbox_recontain`/`run_onbox_rebuild`/`run_onbox_rm_container`/`run_onbox_rm_image`) forwarding to the generic `run_recontain`/`run_rebuild`/`run_rm_container`/`run_rm_image`, so the documented executor surface is preserved and no delegate becomes unreferenced. In [lib/mounts.sh](../../../lib/mounts.sh), `mount_volume_args` now takes the precomputed write srcs/dsts namerefs (plus `container` and `project`, the latter retained beyond the plan's four-parameter listing because the emitted `<slug>.<container>.write.<dest-slug>` volume names embed the project slug) instead of re-parsing the defaults file and CLI specs, eliminating the write-mount double parse while emitting identical `-v` tokens. The redundant explicit `ensure_base_image` calls in the onbox branches are dropped per the plan; the internal probes in `create_sandbox`/`run_recreate` do not actually cover the onbox/base arm (they sit in the non-onbox `else`), which is recorded as an issue rather than silently extended, since the executor-level tests pin the onbox paths as probing no image.

`make test-unit` (287/287) and `make test-e2e` (76/76) pass; `make lint` and `make format` are clean. [MAP.gen.md](../../../MAP.gen.md) entries for the three modified files (plus the `defaults/write.mounts` parse-role note) were updated. The plan document is marked complete in the plans index. No dispute or verdict documents were involved; one new issue document was created: [onbox create/recontain no longer ensure the base image exists](../issues/onbox-base-image-no-longer-probed.gen.md), describing the fresh-machine regression caused by the plan's false premise about the internal base-image probes.
