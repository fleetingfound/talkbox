# Tests: Phase 8a lifecycle verbs remove and recreate named volumes

Linked plan: [phase-8a-lifecycle-named-volume-cleanup.gen.md](../plans/phase-8a-lifecycle-named-volume-cleanup.gen.md)

Summary: this phase makes the lifecycle verbs remove and recreate the explicitly-created named volumes (`<slug>.<container>.gitdir`, `<slug>.netbox/offbox.worktree`, `<slug>.netbox/offbox.write.<dest-slug>`) that `podman rm -f --volumes` leaves orphaned — `--rm-container` deletes them, while `--recontain`/`--rebuild` delete them so the populate/gitdir-volume steps recreate them cleanly — resolving [lifecycle-verbs-leave-named-volumes-orphaned.gen.md](../issues/lifecycle-verbs-leave-named-volumes-orphaned.gen.md) and implementing the "associated volumes" requirements of the image and container management section of [SPEC.md](../../../SPEC.md).

## New tests

- `test/unit/lifecycle.bats` — `plan_volume_rm emits podman volume rm -f only when the volume exists` verifies the new `plan_volume_rm` helper directly: with `volume_exists` stubbed true it emits exactly `podman volume rm -f <name>`, and with the volume absent it emits nothing, exercising the plan's interface "`plan_volume_rm <plan-nameref> <volume-name>` — emits `podman volume rm -f <volume-name>` when the volume exists".
- `test/unit/lifecycle.bats` — `recontain plan removes only the volumes that exist` verifies the `volume_exists` guard on the onbox recontain path: with no volumes present no removal tokens are emitted, and once the gitdir volume is stubbed present a single `podman volume rm -f talkbox-proj.onbox.gitdir` token appears (the plan's "Add cases verifying that only existing volumes are emitted for removal (the `volume_exists` guard)").
- `test/unit/lifecycle.bats` — `rm-container volume removal is guarded by volume existence` applies the same guard check to `plan_netbox_rm_container`: zero removal tokens when nothing exists, exactly the worktree volume removed when only it is present, and the gitdir volume left alone when absent.
- `test/unit/lifecycle.bats` — `netbox rm-container plan removes the write volumes when write dests are supplied` passes a non-empty dest array and asserts a third removal token for `talkbox-proj.netbox.write.talkbox-wdata` alongside the worktree and gitdir volumes, covering "write volumes appear when write-mount dests are supplied" and the new trailing nameref parameter of `plan_netbox_rm_container`.

## Tests edited

All edits replace assertions that the lifecycle plans contain only `rm`/`build`/`commit`/`run`/`create`/`start` subcommands with assertions that they also contain `podman volume rm -f <name>` tokens for the container's associated named volumes, as the plan requires: "Update every `plan_recontain`/`plan_rebuild`/`plan_*_rm_container` assertion to account for the new `volume rm` subcommands in the emitted plan sequence (e.g. the `plan_subcommands` sequence gains `volume` steps, and the plan contains `podman volume rm -f <name>` tokens for the gitdir/worktree/write volumes)". A `stub_volumes` helper (redefining `volume_exists`) was added so each plan test can deterministically declare which named volumes exist, mirroring the plan's "Removal is guarded by an existence check (mirroring `plan_gitdir_volume`'s `volume_exists` guard on creation)".

### Unit

- `test/unit/lifecycle.bats` — `recontain plan removes, recreates and starts the container`: with the gitdir volume stubbed present, now expects `plan_subcommands` `rm\nvolume\ncreate\nstart` and the token `podman volume rm -f talkbox-proj.onbox.gitdir`, per the plan's "In `plan_recontain` and `plan_rebuild` (onbox): emit named-volume removal for the onbox gitdir volume after the `podman rm -f --volumes` step and before `plan_gitdir_volume`".
- `test/unit/lifecycle.bats` — `rebuild plan rebuilds the base image then recreates and starts`: same onbox gitdir-removal assertion, sequence `build\nrm\nvolume\ncreate\nstart`.
- `test/unit/lifecycle.bats` — `rm-container plan removes the container with its volumes`: now asserts the gitdir volume removal token alongside `podman rm -f --volumes`, since the plan's external behaviour states "`onbox --rm-container` removes the `onbox` container and its gitdir named volume (`<slug>.onbox.gitdir`)".
- `test/unit/lifecycle.bats` — `netbox recontain plan commits the source, populates and recreates the container` and the offbox analogue: with the worktree and gitdir volumes stubbed present, expect two removal tokens and sequences `commit\nrm\nvolume\nvolume\nrun\ncreate\nstart`, per "In `plan_netbox_recontain`, `plan_netbox_rebuild`, `plan_offbox_recontain`, `plan_offbox_rebuild`: emit named-volume removal for the worktree, gitdir and write volumes after the `podman rm -f --volumes` step and before the populate ... and `plan_gitdir_volume` steps".
- `test/unit/lifecycle.bats` — `netbox recontain plan skips the commit when the source is the base image`: retains the no-commit assertion while gaining the two worktree/gitdir removal tokens (sequence `rm\nvolume\nvolume\nrun\ncreate\nstart`).
- `test/unit/lifecycle.bats` — `netbox recontain plan populates the write volumes when present` and the offbox analogue: with the write volume also stubbed present, expect three removal tokens and sequences `commit\nrm\nvolume\nvolume\nvolume\nrun\nrun\ncreate\nstart`.
- `test/unit/lifecycle.bats` — `netbox rebuild plan rebuilds the base image, commits, populates and recreates` and the offbox analogue: expect sequences `build\ncommit\nrm\nvolume\nvolume\nrun\ncreate\nstart` plus the gitdir removal token.
- `test/unit/lifecycle.bats` — `netbox rm-container plan removes the container and its root image` and the offbox analogue (renamed `... removes the container, its root image and named volumes`): updated per "Update the `plan_netbox_rm_container`/`plan_offbox_rm_container` unit tests to pass the new dest-array parameter", now passing the empty `DSTS` array and asserting the worktree and gitdir removal tokens alongside `rm`/`rmi`.

### End-to-end

- `test/e2e/lifecycle.bats` — `onbox --rm-container removes the persistent container` (renamed `... and its gitdir named volume`): now also asserts `podman volume exists` returns true before removal and false afterwards, per the plan's "Add a test verifying that after `onbox --rm-container`, the gitdir named volume no longer exists (`podman volume exists` returns false)" — consolidated into the existing test rather than added as a separate one to keep the suite within the default `GLOBAL_TEST_TIMEOUT`.
- `test/e2e/lifecycle.bats` — `onbox --recontain recreates the container and starts it`: strengthened per the plan's "Strengthen the existing `onbox --recontain` test to assert that the gitdir volume is recreated fresh — e.g. commit inside the container, recontain, and confirm the previous container commit is no longer present in the git history of the recontained container". The test now commits `container-commit` inside the container (host history `host-initial`), confirms it is present, recontains, and asserts the commit is no longer in the container's `git log` — before this phase the stale gitdir volume keeps the old history, so the test fails.
- `test/e2e/netbox-offbox.bats` — `netbox --rm-container removes the container and its root image` (renamed `... its root image and named volumes`): the netbox container is now created with a write mount (`--write <dir>:/talkbox/wdata`) and `netbox --rm-container` is invoked with the same write mount; the test asserts the worktree, gitdir and write named volumes exist before removal and no longer exist afterwards, per the plan's "Add a test verifying that after `netbox --rm-container` (with a write mount), the worktree, gitdir and write named volumes no longer exist" (consolidated into the existing netbox rm-container e2e test so the onbox/netbox setup is reused and the suite stays within the default timeout).

## Tests removed

- None. No pre-existing test is inconsistent with the plan: the plan only adds named-volume removal tokens to the lifecycle plans and threaded write-dest parameters, changing no existing plan output that the other unit/e2e tests assert on (`rm-image` plans, `plan_onbox`/`plan_netbox`/`plan_offbox`, GPU passthrough, inheritance and populate planners are all unaffected), and the new behaviour fails every affected pre-existing assertion only where the plan requires those assertions to be updated.
