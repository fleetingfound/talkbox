# Phase 23a test record: write-mount folder validation and failed-creation volume rollback

Implements [Phase 23a](../plans/phase-23a-write-mount-validation-and-rollback.gen.md), which resolves the [write-mount-file-source-unvalidated issue](../issues/write-mount-file-source-unvalidated.gen.md) by making `mount_entries` die with a `talkbox:` diagnostic when a write-mode source resolves to a non-directory, and by rolling back the auto-created named volumes and any partially created container when the create/recreate `execute_plan` fails, so a failed creation leaves no orphaned podman state. This record describes the tests written for that behaviour; all new tests currently fail (red) and are expected to pass once the plan is implemented.

## New tests

Twelve tests, one per plan test clause:

- `test/unit/mounts.bats` (4) — the write-mode directory check at the `mount_entries` choke point, exercised through `mount_args`/`mount_entries` with the podman-free helpers:
  - *write mode dies with a talkbox diagnostic for a file source while a directory source parses* — an existing directory still parses to its `-v src:dest` pair, while a file source exits non-zero with a `talkbox:` message naming the file (plan: "a file source and a nonexistent source die with a `talkbox:` diagnostic").
  - *write mode dies with a talkbox diagnostic for a nonexistent source* — a `--write` spec whose source path does not exist exits non-zero with a `talkbox:` message naming it.
  - *write mode dies with a talkbox diagnostic for a defaults-file file source* — the same check is reached through a `defaults/write.mounts` line (plan: "Both the defaults file and the CLI specs … flow through this single choke point").
  - *read mode accepts file sources while write mode refuses the same source* — read mode still parses a file source to `-v <file>:/host/read/<basename>:ro` unchanged while the identical write-mode spec dies (plan: "read-mode parsing is unchanged"; `SPEC.md` *read-only mounts*: "Read-only mounts may be either files or folders").
- `test/unit/dispatcher.bats` (4) — dispatcher-level refusals over the logging podman shim:
  - *talkbox.sh onbox refuses a file write source with a talkbox diagnostic and no podman call*, *talkbox.sh netbox refuses a file write source …*, *… a nonexistent write source …*, *… a defaults-file file-source write spec …* — each drives `talkbox.sh <container>` as a subprocess with the offending write spec and asserts a non-zero exit, a `talkbox:` diagnostic naming the source, and an empty shim log, i.e. the failure surfaces before any `podman volume create` or populate `podman run` reaches podman (plan: "fails with a `talkbox:` diagnostic naming the offending source, before any podman container or volume is created"). The onbox and netbox variants cover both `container_action` write-parse branches.
- `test/unit/netbox-offbox.bats` (2) — executor rollback over the logging podman shim, with `PODMAN_VOLUMES` seeded to stand in for the volumes podman auto-creates during populate:
  - *a failed netbox create plan rolls back the named volumes and reports a talkbox error* — the create path (`run_netbox`) with a write mount and `PODMAN_FAIL_PATTERN='cp -a'` failing the populate plan must exit non-zero with a `talkbox:` diagnostic, log `podman volume rm -f` for the worktree, gitdir and write volumes, and never reach `podman start` or any `podman exec` (plan: "on plan failure they stop and remove the partially created container … and remove the named volumes the plan references — the worktree volume, the gitdir volume and the write volumes derived from the parsed write-mount dests — then report the failure with a `talkbox:` diagnostic").
  - *a failed netbox recontain start rolls back the partial container and named volumes with a talkbox error* — the recreate path (`run_netbox_recontain`) with `PODMAN_FAIL_PATTERN` failing the plan's final `podman start` must exit non-zero with a `talkbox:` diagnostic and log, after the failed start, both the removal of the partially created container and `podman volume rm -f` for the worktree, gitdir and write volumes; the pre-recreate `rm -f --volumes` and volume removals the plan itself emits sit before the start, so the after-start line-number assertions pin the rollback rather than the plan's own steps. This is the only plan shape in which a partial container can exist (`podman create` precedes `podman start`).
- `test/e2e/netbox-offbox.bats` (2) — external usage against real podman:
  - *netbox --write with a file source is refused with a talkbox diagnostic and leaves no named volumes* — non-zero exit, `talkbox:` diagnostic naming the file, and `podman volume ls` filtered on the project slug printing nothing, plus no netbox container.
  - *a failed netbox populate leaves no named volumes and no container* — a write-mount source directory made unreadable (`chmod 000`, the plan's "an unreadable source directory" cause) makes the populate `cp` fail; the invocation must exit non-zero with a `talkbox:` diagnostic, leave no named volumes matching the project slug, and no container (plan: "the failure is reported with a `talkbox:` diagnostic and the non-zero exit status propagates").

All twelve are observed failing under the current implementation — the mount and dispatcher tests at their `talkbox:`/exit-status assertions (the current code accepts any write source, or aborts under `set -e` with a raw `cp` diagnostic), and the rollback tests at the absent non-zero exit/`talkbox:` diagnostic and, for the recreate case, the absent after-failure removals. None fails from a test-implementation error or a timeout.

## Tests edited

Thirteen tests were edited; no assertions were weakened or dropped — each edit only replaces a fixture that pointed a write-mount spec at a path that does not exist on the host with a real temporary directory created in the test. The edits are required because the plan makes `mount_entries` die when a write-mode source is not an existing directory, and these tests previously relied on the unvalidated parse accepting fictional sources such as `/some/dir/data`, `/host/var`, `/host/data`, `/first`, `/cli` and `/def` (`SPEC.md` *read-write mounts*: "Read-write mounts must be folders on the host, not arbitrary files"; plan: "when the mode is `write`, each resolved source must be an existing directory, otherwise it dies with a `talkbox:` message naming the source"). Without the fixture change each test would die during the write-mount parse after the plan is implemented, contrary to the requirement that all tests pass post-implementation. The tests' own targets — default-dest derivation, inline-comment stripping, read/write independence, dest-collapse and volume naming/populate-source threading — are preserved; default dests and volume names are unchanged because they derive from the dest (or the created directory's basename), and the populate-source assertions now name the created directory.

- `test/unit/mounts.bats` (4): *mount_args derives a write default dest from the source basename* (`/some/dir/data` → created `$BATS_TEST_TMPDIR/data`, dest assertion becomes `$dir:/host/write/data`); *mount_entries strips an inline comment from CLI --read and --write specs* (write spec `/a  # a comment` → `$dir  # a comment`, read part untouched); *mount_args treats read and write modes independently* (`/src` → created `$BATS_TEST_TMPDIR/src` for both modes); *mount_args lets a CLI write spec override an identical defaults-file write dest keeping the CLI source* (`/def`, `/cli` → created directories written into the defaults file and the CLI spec).
- `test/unit/containers.bats` (1): *run_onbox forwards pasta -T ports and applies read mounts read-only and write mounts as bind-mounts* (`/host/var` in the defaults write.mounts → created `$BATS_TEST_TMPDIR/var`; create-line token assertion follows the created path).
- `test/unit/dispatcher.bats` (6): *talkbox.sh onbox bind-mounts CLI write specs and never populates volumes*, *talkbox.sh netbox mounts a CLI write spec as a volume named <slug>.netbox.write.<dest-slug> and populates it from the host*, *talkbox.sh offbox mounts a CLI write spec as a volume named <slug>.offbox.write.<dest-slug>*, *talkbox.sh netbox derives the write-volume dest-slug from the dest basename path* (all `--write /host/data:…` → created `$BATS_TEST_TMPDIR/wdata`; populate-source token follows), *talkbox.sh netbox collapses identical write dests into a single volume populated from the last source* (`/first`, `/cli` → created directories), *talkbox.sh netbox merges defaults-file and CLI write specs in order* (`/def`, `/cli` → created directories; volume-name assertions unchanged).
- `test/unit/netbox-offbox.bats` (2): *run_netbox keeps read mounts read-only and write mounts as volumes, populating them from the host* and *run_offbox emits write-mount volumes and read-only read mounts, populating from the host* (the `mount_entries` write spec `/host/data:/talkbox/wdata` → created `$BATS_TEST_TMPDIR/wsrc`; the read-mount spec and all volume-name tokens unchanged, the populate-source token follows the created directory).
