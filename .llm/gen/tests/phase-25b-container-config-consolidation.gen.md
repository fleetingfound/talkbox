# Tests: Phase 25b per-container configuration consolidation

Test revision for [Phase 25b: per-container configuration consolidation of the container implementation](../plans/phase-25b-container-config-consolidation.gen.md), a behaviour-preserving refactor which will make the three containers pure configuration over a single common implementation (`lib/definitions.sh`) — the revision pins today's exact podman command lines and function outputs against the surviving surfaces (`*_of` dispatchers, `plan_populate_and_create`, the executor cores) so that the refactor must keep them byte-identical.

Per the pin flow, the revised suite is green against the current, unmodified (post-Phase 25a) implementation; no core file was touched. No test references any function the plan drops (`onbox/netbox/offbox_container_name`, `netbox/offbox_worktree_volume`, `netbox/offbox_write_volume`, `netbox/offbox_root_image`, `container_net_suffix`, `plan_netbox_populate`, `plan_offbox_populate`), and the unspecified onbox values of `root_image_of`/`write_volume_of` are deliberately not pinned (plan invariant 1).

## Tests implemented

- `test/unit/naming.bats` — `container_name_of` names each container `<project-slug>.<container>` (data-driven over all three containers); `worktree_volume_of` names the netbox/offbox worktree volumes and maps the onbox worktree to the host project path (the bind-mount degenerate case); `write_volume_of` names the netbox/offbox write volumes from a dest-slug; `root_image_of` names the netbox/offbox root images. All load `lib/containers.sh` (where the dispatchers live) instead of `lib/naming.sh` only.
- `test/unit/netbox-offbox.bats` — the populate coverage re-expressed through the surviving `plan_populate_and_create` (with the podman shim): every `podman run` in the netbox/offbox plans opens with the exact no-network prefix tokens and there are exactly two populate runs (worktree + write); a base source seeds both the worktree and write volumes from the host and never targets the gitdir volume. Plus a new executor test pinning the populate policy as a target-container property: `run_container netbox` always seeds from the host even under an explicit `--inherit offbox` (commit present, host `:ro` source, no offbox volume source) — previously unpinned.
- `test/unit/containers.bats` — the former all-onbox shared-pipeline executor tests re-expressed as data-driven loops over `onbox`, `netbox` and `offbox` (see edited below); per-container expectations live as data: pasta suffix, write style (bind vs named volume), worktree mount token (host path vs worktree volume), gitdir volume name and nft applicability (onbox/netbox yes, offbox none).

## Tests edited

- `test/unit/naming.bats` — the `project_base`/`slugify`/`project_slug`/`base_image_name`/`dest_slug`/`gitdir_volume` tests are unchanged.
- `test/unit/netbox-offbox.bats` — name-construction call sites replaced per the plan's supersession list: `netbox_write_volume`/`offbox_write_volume` → `write_volume_of` in the two read/write-mount tests; `netbox_container_name`/`offbox_container_name` → `container_name_of` in the two start-time-tail tests; the three `*_container_name` calls in the `run_recreate` ordering loop → `container_name_of`. The `inherit_source`/`source_exists`, `plan_volume_populate`, executor and rollback tests are otherwise unchanged, as the plan retains them.
- `test/unit/containers.bats` — rewritten as the symmetric shared-pipeline file: every onbox executor test's assertions are retained inside loops over all three containers (create args, base-image probe/build, pasta string and `-T` port threading, read/write mount style, worktree mount, dotfiles/art, `--name`/`--init`/sleep ordering, interactive flags, git mounts and gitdir volume lifecycle, git identity and prompt env vars, GPU options, interactive shell and command execution with stop semantics, setup failure, create-vs-recontain byte-identity, nft error and setup error messages). Genuinely per-container expectations (pasta suffix, write style, nft applicability) remain as per-container data in the loops; the two `onbox_container_name` call sites became `container_name_of`.
- `test/unit/lifecycle.bats` — the `run_recreate`/`run_rm_image`/planner tests are unchanged apart from the folds below; the per-container recreate tests keep their per-container inheritance data (commit sources, populate, nft, image handling).
- `test/unit/dispatcher.bats` — consistency folds of the per-container copies of the shared pipeline (plan's "consistency with the consolidation" clause): the three write-spec tests fold into one loop over the three containers with style data (onbox bind-mount and no populate runs vs netbox/offbox named volume populated from the host); the dest-slug derivation loops over netbox/offbox; `--port` threading loops over all three with the per-container pasta suffix; `--rm-container` folds into one data-driven loop over the three containers (per-container volume sets, root-image presence, inspect discovery); `--rm-image` loops over all three; the write-source refusal tests (file source, nonexistent source, defaults-file file source) loop over all three containers. The per-container-semantics tests (create/recontain/rebuild, inheritance) are unchanged.
- `test/unit/git-transport.bats` — the single `onbox_container_name` call site replaced by `container_name_of`; otherwise unchanged, as the plan retains.

## Tests removed

All removals are identified as superseded by the plan (either invoking a function it drops, or per-container copies of the shared pipeline folded per its consistency clause); every assertion lives on inside a folded or re-expressed test:

- `test/unit/naming.bats` — the ten per-container one-liner tests (`onbox_container_name` ×2, `netbox_container_name`, `offbox_container_name`, `netbox_worktree_volume`, `offbox_worktree_volume`, `netbox_write_volume`, `offbox_write_volume`, `netbox_root_image`, `offbox_root_image`): the plan deletes the nine one-liner functions and re-expresses this coverage against the `*_of` dispatchers.
- `test/unit/netbox-offbox.bats` — the three tests invoking `plan_netbox_populate`/`plan_offbox_populate` directly (no-network prefix, netbox host-seeding/gitdir-never-populated, offbox base-source host-seeding/gitdir-never-populated): the plan drops both planners and re-expresses the coverage through `plan_populate_and_create` and the executors.
- `test/unit/lifecycle.bats` — the eight per-container rm-container tests (onbox gitdir-only ×2 phases, netbox/offbox full-removal pairs, netbox/offbox inspected-write-volume pairs, netbox/offbox omit-rmi pairs, netbox+offbox volume-existence guard): folded into the five data-driven removal tests listed under tests implemented, with the onbox "only the gitdir volume, no root image" expectation as the onbox column of the per-container data.
- `test/unit/dispatcher.bats` — the per-container copies folded away as listed under tests edited (onbox/netbox/offbox write-spec mounts, netbox dest-slug, netbox/offbox/onbox `--rm-container`, onbox `--rm-image`, onbox+netbox file-source refusals).
