# Tests: Phase 11b — E2e test teardown hygiene

Linked plan: [phase-11b-e2e-teardown-hygiene.gen.md](../plans/phase-11b-e2e-teardown-hygiene.gen.md)

Linked issue: [e2e-fresh-container-exec-races-entrypoint.gen.md](../issues/e2e-fresh-container-exec-races-entrypoint.gen.md)

Summary: this phase is itself a test-only modification which consolidates the container/image/volume cleanup sequence duplicated across the e2e teardowns into a shared `teardown_talkbox` helper in [test/e2e/helpers.bash](../../../test/e2e/helpers.bash) and switches all six e2e suites to call it — including [test/e2e/onbox.bats](../../../test/e2e/onbox.bats), whose minimal teardown leaked a `<slug>.onbox.gitdir` named volume after every test and removed nothing else — so that no container, root image or named volume survives a test run and repeated suite runs no longer accumulate the leftover state that slows podman and trips the `image_in_use` guard (the state-pollution dimension of the linked issue); no aspect of `SPEC.md` / `SPEC.gen.md` or of the talkbox implementation is altered, and the full e2e suite continues to pass 68/68 (the count referenced as 67/67 in the issue predates the Phase 11a addition) across successive runs with zero leaked state.

## New tests

- None. The plan's Test section requires no new test case ("No additional tests are required beyond verifying that the full e2e suite continues to pass 67/67 with the refactored teardowns. The key validation is running the suite multiple times in succession ... and confirming no state leaks between runs"), so the pinning deliverable is the refactor below plus the repeated-suite-run validation.
- `test/e2e/helpers.bash` — `teardown_talkbox <slug> [extra-container...]` is added as a new shared teardown helper (test-support code rather than a test case), placed alongside `sdrun`, `mk_project` and `mk_talkbox` as the plan requires. It performs, in order: `podman rm -f -v` of `<slug>.onbox`, `<slug>.netbox`, `<slug>.offbox` plus any non-empty extra containers; `podman rmi` of `<slug>.netbox.root` and `<slug>.offbox.root`; and `podman volume ls -q --filter "name=<slug>"` / `podman volume rm -f` of every match. All removals are best-effort (`> /dev/null 2>&1 || true`, `--force`), so the absence of any container, volume or image is tolerated exactly as in the inline teardowns it replaces; empty extra-container arguments are filtered so an unset `PLAIN_CTR` can be passed unconditionally. Validation: after the refactor, two consecutive full `make test-e2e` runs both passed 68/68 and left zero new containers (`podman ps -aq`), zero `<slug>.*.root` images and zero `tmp-*` volumes behind, whereas a single pre-refactor run left 12 leaked `tmp-*.onbox.gitdir` volumes (one per `onbox.bats` test).

## Tests edited

Every edit below replaces a duplicated inline cleanup with the shared helper; in the happy path the cleanup is behaviour-preserving, and each pre-refactor teardown is defective against the project implementation only in the state-pollution scenarios the plan describes (a partially failed or interrupted test leaves state that later runs trip over):

- `test/e2e/onbox.bats` — `teardown()` previously ran `podman rm -f -v "$CTR"` and nothing else. That fails against the suite's own usage: `rm -v` removes only anonymous volumes, and the onbox gitdir volume is created as the *named* volume `<slug>.onbox.gitdir`, so every one of the file's 12 tests leaked its gitdir volume (measured: one full pre-refactor run left exactly 12 orphaned `tmp-*.onbox.gitdir` volumes) and any netbox/offbox containers or `<slug>.*.root` root images left behind by a mid-test failure were never removed. The refactored teardown calls `teardown_talkbox "$(project_slug_e2e "$PROJECT")"` before the host-side `rm -rf`, removing all three canonical containers, both root images and every slug-matching named volume. This is the plan's stated fix for the sole source of the named-volume leak.
- `test/e2e/lifecycle.bats` — `teardown()` previously removed only `$CTR` (the onbox container) plus slug-matching volumes inline, after killing `HOST_SRV_PID`. The inline kill of `HOST_SRV_PID` remains (per the plan); the container/volume lines are replaced by `teardown_talkbox "$PROJECT_SLUG"`. The old form passed on the happy path (lifecycle tests create only onbox containers) but left netbox/offbox containers and root images unremoved in partial-failure scenarios, the accumulation the issue describes.
- `test/e2e/netbox-offbox.bats` — `teardown()` previously ran the full canonical three-container removal, both root-image `rmi` and the inline volume loop; it is replaced by `teardown_talkbox "$PROJECT_SLUG"`. The setup variables `ONBOX_CTR` and `OFFBOX_ROOT` were used only by the old inline teardown and are removed (shellcheck SC2034 would otherwise fail `make lint`); `NETBOX_CTR`, `OFFBOX_CTR` and `NETBOX_ROOT` remain in use by the tests themselves.
- `test/e2e/git-identity.bats` — `teardown()` is replaced by `teardown_talkbox "$PROJECT_SLUG"`, and the setup variables `ONBOX_CTR`, `NETBOX_CTR` and `OFFBOX_CTR`, which were referenced only by the replaced inline teardown, are removed to keep `make lint` clean.
- `test/e2e/git-transport.bats` — `teardown()` previously removed the three canonical containers, conditionally removed `PLAIN_CTR` (a plain-folder project's onbox container created by the non-git-project test), removed both root images and ran the inline volume loop; it is replaced by `teardown_talkbox "$PROJECT_SLUG" "$PLAIN_CTR"` passing `PLAIN_CTR` as the extra container, followed by the unchanged `rm -rf "$PROJECT" "$TALKBOX" "${EXTRA_DIRS[@]}"` (the `EXTRA_DIRS` host-side cleanup stays inline per the plan's deferral). The empty-string `PLAIN_CTR` default is tolerated by the helper's empty-argument filter, preserving the old conditional's no-op behaviour.
- `test/e2e/merge-sync.bats` — same replacement as git-transport: `teardown_talkbox "$PROJECT_SLUG" "$PLAIN_CTR"` plus the unchanged `EXTRA_DIRS` `rm -rf`. The setup variables `NETBOX_CTR` and `OFFBOX_CTR` were referenced only by the old inline teardown and are removed (shellcheck SC2034); `ONBOX_CTR` remains in use by the stopped-container sync test.

## Tests removed

- None. No test case was removed or changed in its assertions; the setup-variable deletions listed above remove only now-dead assignments, and no pre-existing test is inconsistent with the plan since the cleanup sequence itself is behaviour-preserving in the happy path and strictly more thorough in partial-failure scenarios.
