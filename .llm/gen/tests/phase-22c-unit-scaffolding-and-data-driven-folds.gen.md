# Phase 22c: unit scaffolding consolidation and data-driven test folds

Implements [phase-22c-unit-scaffolding-and-data-driven-folds.gen.md](../plans/phase-22c-unit-scaffolding-and-data-driven-folds.gen.md), which resolves the remaining items of the [duplication and reusable-abstraction review](../../reviews/duplication-abstraction-review.gen.md) — §13 (per-file unit-test scaffolding) and §16 (container-fold repetition and the line-number extraction idiom) — by moving the identical per-file `load_*_plan`, `use_podman_shim`, `plan_subcommands` and `array_contains`/`array_has_none` copies into [test/unit/helpers.bash](../../../test/unit/helpers.bash) (plus a generic `log_line_no <pattern> <file>` helper in both helpers files), joining the [dispatcher.bats](../../../test/unit/dispatcher.bats) shim variant to the shared helper with an explicit image argument, and folding the byte-identical container-parameterised test families into data-driven loops following the established [git-transport.bats](../../../test/e2e/git-transport.bats) pattern. No production file is touched and no `SPEC.md` aspect changes.

## New tests

Five tests, each a container-parameterised fold replacing superseded byte-identical per-container tests with identical coverage (same invocations, same assertions, per loop iteration):

- [test/unit/lifecycle.bats](../../../test/unit/lifecycle.bats) — `run_rm_image prunes external working containers before removing the base image for every container`: loops `for c in onbox netbox offbox`, per iteration truncating the log, invoking `run_${c}_rm_image` and asserting the external-prune → `rm -f ext1` → `rmi talkbox/base:latest` ordering exactly as each of the three replaced tests did. The loop body's log truncation keeps every container's line numbers scoped to its own iteration.
- [test/unit/netbox-offbox.bats](../../../test/unit/netbox-offbox.bats) — `run_netbox and run_offbox recontain and rebuild order start, the nft install, setup.sh and stop per container`: loops `netbox offbox` (names, container names and per-container expectations held in parallel arrays: the step that must precede `setup.sh` — the nft deny install for netbox, the start for offbox — and a pattern that must be absent from the log, empty for netbox, `nsenter` for offbox), with an inner `recontain rebuild` phase loop replacing the two tests' internal duplication; the shared assertion block (existence, pre-setup < setup < stop, absence check) runs once per phase, and the loop body contains no per-container conditional.
- [test/e2e/git-identity.bats](../../../test/e2e/git-identity.bats) — `onbox, netbox and offbox container git identity matches the host user.name and user.email` and `onbox, netbox and offbox commits are attributed to the host git identity`: each loops `for c in onbox netbox offbox` running the identical `run_talkbox` invocation and output assertions the six replaced tests carried per container.
- [test/e2e/deny-allow.bats](../../../test/e2e/deny-allow.bats) — `--deny-ip blocks a denied address while a non-denied address remains reachable in onbox and netbox`: one HTTP fixture serves both iterations of `for c in onbox netbox`, each asserting `DENIED-BLOCKED`, `ALLOWED-REACHABLE` and no `talkbox:` error exactly as the two replaced tests did; the IPv6 variant and the nft-installer test stay separate per the plan (substantively different skip guards and behaviour).

## Tests edited

Scaffolding replacements identified by the plan; no test's assertions changed unless noted:

- [test/unit/containers.bats](../../../test/unit/containers.bats), [test/unit/netbox-offbox.bats](../../../test/unit/netbox-offbox.bats), [test/unit/lifecycle.bats](../../../test/unit/lifecycle.bats) — the identical `load_onbox_plan`/`load_netbox_plan`/`load_lifecycle_plan` indirections, per-file `use_podman_shim` copies and (in netbox-offbox/lifecycle) `plan_subcommands` plus netbox-offbox's `array_contains`/`array_has_none` were deleted; call sites now use the shared `load_container_libs`, `use_podman_shim`, `plan_subcommands` and array helpers in [test/unit/helpers.bash](../../../test/unit/helpers.bash), whose bodies are identical to the per-file copies. The per-file `setup()` array initialisations and lifecycle's `plan_has_volume_rm`/`stub_volumes` stay local (they are not identical across files / not named by the plan).
- [test/unit/dispatcher.bats](../../../test/unit/dispatcher.bats) — its local `use_podman_shim` variant was deleted and every call site joins the shared helper with the base image passed explicitly (`use_podman_shim "$BASE_IMAGE"`), with a comment explaining why: the tests drive `talkbox.sh` as a subprocess and cannot source `lib/naming.sh` for `base_image_name`, the option the plan offers for this variant. `PODMAN_IMAGES` receives the same value as before.
- The `grep -n <pattern> "$PODMAN_LOG" | head -n 1 | cut -d: -f1` idiom sites in [test/unit/containers.bats](../../../test/unit/containers.bats) (4), [test/unit/netbox-offbox.bats](../../../test/unit/netbox-offbox.bats) (13, including the folded test) and [test/unit/lifecycle.bats](../../../test/unit/lifecycle.bats) (via the fold) became `log_line_no <pattern> "$PODMAN_LOG"` calls; `podman_line_no` is now the `PODMAN_LOG` specialisation of the new generic `log_line_no`. The two local-log sites in [test/e2e/git-identity.bats](../../../test/e2e/git-identity.bats) use the equivalent helper added to [test/e2e/helpers.bash](../../../test/e2e/helpers.bash). Both helpers return the first-match 1-based line number, empty when absent — the idiom's exact semantics.
- Families deliberately not folded, per the plan's guardrails (substantive per-container differences in assertions, preconditions or expected behaviour): the onbox/netbox/offbox create-path nft/setup ordering tests in [netbox-offbox.bats](../../../test/unit/netbox-offbox.bats), the executor-specific lifecycle tests there, the IPv6 and nft-installer deny-allow tests, and the container-specific git-transport tests.

## Tests removed

Superseded by the container-parameterised equivalents above, exactly as the plan's superseded-tests list identifies (replaced with identical coverage across all loop iterations):

- [test/unit/lifecycle.bats](../../../test/unit/lifecycle.bats) — the three `run_rm_image prunes external working containers before removing the base image` tests (`run_rm_image`/`run_netbox_rm_image`/`run_offbox_rm_image` variants; byte-identical apart from the executor name).
- [test/unit/netbox-offbox.bats](../../../test/unit/netbox-offbox.bats) — the `run_netbox recontain and rebuild run setup.sh after the nft deny install and before stopping the container` and `run_offbox recontain and rebuild run setup.sh after start and before stopping the container, with no nft step` ordering pair (each duplicating its assertion block internally for the recontain and rebuild phases).
- [test/e2e/git-identity.bats](../../../test/e2e/git-identity.bats) — the six same-shape tests (two assertions × three containers: `<c> container git identity matches the host user.name and user.email`, `<c> commits are attributed to the host git identity`).
- [test/e2e/deny-allow.bats](../../../test/e2e/deny-allow.bats) — the `onbox --deny-ip blocks a denied address while a non-denied address remains reachable` and `netbox --deny-ip blocks a denied address…` pair.

Net effect: the unit suite goes from 305 to 302 tests and the e2e suite from 77 to 72 — the thirteen superseded tests (3 + 2 unit, 6 + 2 e2e) are replaced by the five folded tests above, with unchanged per-container coverage.

`make test-unit` (302/302), `make test-e2e` (72/72, 0 skips), `make lint` and `make format` all pass on the consolidated helpers and the folded/edited bats files. No production file changed; external-facing behaviour is unchanged.
