# Phase 23b test record: `--rm-container`/recreate write-volume removal via container-mount inspection

Implements [Phase 23b](../plans/phase-23b-rm-container-write-volume-inspection.gen.md), which resolves the [`--rm-container` leaks write volumes unless `--write` is repeated](../issues/rm-container-write-volumes-need-repeated-write.gen.md) issue by having `plan_container_volumes_rm` discover the container's write volumes through a `podman inspect` of its `Mounts` (filtered on the `<project-slug>.<container>.write.` prefix) instead of the removal invocation's own write-dst list, so `netbox`/`offbox --rm-container` remove every write volume the container actually used without `--write` being repeated and the `--recontain`/`--rebuild` paths leave no stale write volume from an earlier mount configuration (`SPEC.md` *image and container management*: "`--rm-container` removes the container, together with associated volumes"; "`--recontain` … recreate the container and all of its associated volumes"). This record describes the tests written for that behaviour; the new and superseded tests currently fail (red) and are expected to pass once the plan is implemented.

## New tests

Six tests, one per plan test clause:

- `test/unit/lifecycle.bats` (4) — plan and executor level over the logging podman shim:
  - *plan_container_volumes_rm emits a volume rm for every write volume the container mounts* — drives `plan_container_volumes_rm` with the new three-argument signature through a plan-printing helper, with the shim's `podman container exists` accepting the netbox container and its `podman inspect` over `Mounts` returning the worktree, gitdir and two write volumes from `PODMAN_INSPECT_MOUNTS`; the plan must contain one `podman volume rm -f` per discovered write volume, exactly one removal per by-name worktree/gitdir volume (no double removal from the inspected non-write mounts), and nothing else (plan: "with a mocked inspect returning write-volume mounts, the plan emits a `podman volume rm` for each discovered write volume").
  - *run_netbox_rm_container removes the inspected write volumes without write dsts* — `run_netbox_rm_container "$PROJECT"` (the plan's dropped-parameter signature) with the container existing and `PODMAN_INSPECT_MOUNTS` naming two write volumes; the log must show the `inspect -f` Mounts inspection before the emitted `podman rm -f --volumes`, then a `podman volume rm -f` for each discovered write volume and no other removal or `podman rmi` (plan: "Since plans are assembled before execution, the container is inspected while it still exists, ahead of the emitted `podman rm`").
  - *run_offbox_rm_container removes the inspected write volumes without write dsts* — the offbox analogue of the same executor behaviour.
  - *run_netbox_recontain removes the previous configuration's write volumes before repopulating* — `run_netbox_recontain` with the netbox container reporting a `talkbox-wdata` write mount while the recreate invocation carries only a new `--write /host/alt:/talkbox/walt` configuration; the stale `talkbox-wdata` volume must still be removed (three `volume rm -f` total) and the new configuration must be repopulated from `/host/alt` (plan: "`--recontain`/`--rebuild` remove the previous configuration's write volumes before repopulating, so no write volume from an earlier mount configuration survives a reconfiguration as a stale volume").
- `test/unit/dispatcher.bats` (1) — dispatcher level over the podman shim:
  - *talkbox.sh offbox --rm-container removes the inspected write volume without repeating --write* — drives `talkbox.sh offbox --rm-container` as a subprocess with the offbox container existing and its mounts reporting `talkbox-proj.offbox.write.talkbox-wdata`; the write volume must be removed with no `--write` flag on the invocation and no root-image `rmi` (plan: "a `--rm-container` invocation without `--write` issues the inspect-based volume removals").
- `test/e2e/netbox-offbox.bats` (1) — external usage against real podman:
  - *netbox --recontain leaves no write volume from the previous write-mount configuration* — creates the netbox with `--write <data>:/talkbox/wdata`, then `netbox --recontain --write <alt>:/talkbox/walt` (a changed configuration); the `talkbox-wdata` volume must be gone, the `talkbox-walt` volume must exist and be populated from the new source (verified through a separate default-verb `netbox -c --noninteractive 'cat /talkbox/walt/new.txt'` because the recreate verbs do not execute a `-c` command), with the command's argument carried on the recontain invocation itself.

All six are observed failing under the current implementation at their write-volume assertions — the shim never reports container mounts today, so no inspect-driven `volume rm` appears in any plan or log, and the stale e2e volume survives both `--rm-container` and the changed-configuration recontain. None fails from a test-implementation error or a timeout.

## Tests edited

Nine tests were edited; no test was removed. Each edit is required either by the plan's signature change (`plan_container_volumes_rm` loses its write-dsts nameref parameter, so the dispatcher's `rm-container` branch and the `run_netbox_rm_container`/`run_offbox_rm_container` executors no longer thread `write_dsts` — plan: "the existing rm-container unit tests which pass the write-dsts parameter must be updated for the new signature") or by the switch of the write-volume removal derivation from the current invocation's dest list to the inspected container mounts (a dsts-derived removal no longer happens after implementation, so tests relying on it must either thread the mount through the shim's inspect or the removal assertion fails).

- `test/unit/lifecycle.bats` (6):
  - *run_netbox_recontain removes and repopulates the write volumes when present* — the removal of `talkbox-proj.netbox.write.talkbox-wdata` was previously produced by the dsts-parameter loop; after implementation it comes from the container inspection, so the test now seeds `PODMAN_CONTAINERS` with the netbox container and `PODMAN_INSPECT_MOUNTS` with its mounts (worktree, gitdir, write volume) while keeping the dsts for repopulation and all removal/populate/count assertions unchanged (`SPEC.md` *read-write mounts*: "The volume is named `<project-slug>.netbox.write.<dest-slug>`" — the volume is an associated volume regardless of which invocation's arguments produced it).
  - *run_netbox_rm_container removes the container, its volumes and its root image when the root image exists* — drops the `dsts` argument, seeds the container and its inspected mounts, and adds no-double-removal pins (`volume rm -f …worktree$`/`…gitdir$` exactly once each, total three removals); it now fails pre-implementation at the absent write-volume removal (plan: "`--rm-container` … remove every `<slug>.<container>.write.<dest-slug>` volume the container actually uses, without `--write` needing to be repeated").
  - *run_netbox_rm_container omits the rmi when the root image does not exist* — drops the `DSTS` argument and adds the no-container pins: no `inspect -f` in the log and no write-prefix removals, because "when the container does not exist, only the by-name removals apply" (plan).
  - *run_offbox_rm_container removes the container, its volumes and its root image when the root image exists* — the offbox analogue of the netbox full-shape edit.
  - *run_offbox_rm_container omits the rmi when the root image does not exist* — the offbox analogue of the omits-rmi edit.
  - *netbox and offbox rm-container volume removal is guarded by volume existence* — drops the `DSTS` arguments and pins that no Mounts inspection is attempted for an absent container in either container type.
- `test/unit/dispatcher.bats` (2):
  - *talkbox.sh netbox --rm-container removes the container, its volumes and its root image* — the invocation keeps no `--write` flag but the test now seeds the existing netbox container and its inspected mounts; the former assertion that no `talkbox-proj.netbox.write` removal appears (`-eq 0`) is replaced by the requirement that the write volume is removed (three removals total), which is the plan's external-facing statement ("`netbox --rm-container` … remove every `<slug>.<container>.write.<dest-slug>` volume the container actually uses, without `--write` needing to be repeated on the removal invocation"); it fails pre-implementation at that removal.
  - *talkbox.sh onbox --rm-container removes only the container and its gitdir volume* — seeds the existing onbox container with its gitdir volume as the only inspected mount, pinning that a non-write mount produces no extra removal and the removal count stays one (plan: "the worktree and gitdir volumes continue to be removed by name" and the discovery filters on the `.write.` prefix).
- `test/e2e/netbox-offbox.bats` (1):
  - *netbox --rm-container removes the container, its root image and named volumes* — drops the `--write "$data:/talkbox/wdata"` repetition from the removal invocation, as the plan explicitly requires ("the existing `netbox --rm-container` e2e test repeats `--write "$data:/talkbox/wdata"` on the removal command — the repetition must be removed so the leak is caught"); it fails pre-implementation because the write volume survives the `--rm-container` without repetition.

Additionally, `test/unit/helpers.bash` was extended (test-harness, not a test): the `make_podman_shim` inspect branch now also answers an inspect whose format ranges over `{{range .Mounts}}` (for `-f` and `--format`) with the space-separated names in `PODMAN_INSPECT_MOUNTS`, emulating the `podman inspect` over `Mounts` that the plan's discovery helper will perform.

## Tests removed

None. No existing test asserts the superseded dsts-derived removal derivation in a way the plan keeps, and every pre-existing test either keeps passing against the current implementation or was edited above so that it also passes once the plan is implemented; nothing that would pass post-implementation was removed.
