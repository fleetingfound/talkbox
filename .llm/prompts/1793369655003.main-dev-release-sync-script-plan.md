Review the structure of branches main and dev. Each commit on main matches the worktree of a commit on dev, except with files matching .coreignore removed. The file .coreignore should be parsed with git using the same rules as for .gitignore.

The commit message on main should include the version number of the release, provided by the user. It should also end with a line `Commit: <hash>` which includes the hash of the dev commit which produced it.

The commit on main should be tagged according to a release number and so should the commit on dev (with the prefix `dev/`). It should be a lightweight tag with a message matching the commit message on main.

There should be an opportunity for the user to customize the commit message on main to include additional release notes as is currently done on `main`.

Plan a shell script on dev in a subfolder .release/ which automates this process. The folder .release/ will be added to .coreignore. Tests will not be implemented for this implementation which should use `@maker.heavy`.
